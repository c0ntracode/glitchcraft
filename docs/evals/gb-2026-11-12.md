# Game Boy evaluation (2026-11-12)

Method: one fresh subagent read `SKILL.md` and followed it on a Game Boy Color ROM with an MBC5 mapper and 64 banks (a private homebrew dump, not included and not named here) for three requests, then wrote a critique. A second agent wrote adversarial tests (`tests/test_gb_extra.py`) and a third compared the SM83 decoder with the gbdev opcode table. Nothing was run in an emulator.

## Scenarios and outcomes

| Request | What the agent did | Verdict |
|---|---|---|
| A published code (`00C-4BE-3BE`) | `decode`/`vet`: patches `$1C4B` from `$3E` to `$00`, compare `$35` does not match, so it does not apply on this dump; effect in game labelled Guess | Honest. It speculated the code was mangled; it is a public code for another game. |
| "More starting gold" from the ROM only | Searched for the constant, found nothing trustworthy, gave **no code**, said an emulator RAM watch is the route | Honest, and the right call. |
| "Screen went blank" | Followed troubleshooting; labelled the cause Inferred and the next try Guess | Worked, but the Game Boy path was missing. |

## Findings and what changed

- troubleshooting had no Game Boy path (banks, compare mismatch, header, unfindable variable): added.
- `make` did not warn for `$0100`-`$014F`: now warns (test added).
- Banks: `SKILL.md` now says to ask the user which bank is live and how to read the bank from an `xrefs` hit.
- Compare-mismatch hint (`make --compare <original>` prints the encoded form for this dump): in troubleshooting.
- Usage errors for `xrefs`/`disasm`/`decode`/`vet` named the command only: now say what is missing (adversarial tests).
- Adversarial tests found nine defects (symlink overwrite by `patch-copy`, write errors as a traceback, banked `xrefs` for relative jumps, RST references, bank range on 32 KB ROMs, past-the-end banks reported as "bank-dependent", empty code lists, non-positive counts, missing-argument messages). All fixed; suite at 270 tests.
- Decoder vs gbdev table: 511 opcodes, no mismatches after style normalisation (see `references/gb.md`).

## Limits

One run per scenario, by a fresh agent that could read the repository; the ROM is the author's own and no emulator was used, so the Game Boy letters are checked only against two published emulator sources until `docs/evals/gb-letters.md` has a result.
