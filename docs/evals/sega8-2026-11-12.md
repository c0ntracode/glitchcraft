# Game Gear / Master System evaluation (2026-11-12)

Method: one fresh subagent read `SKILL.md` and followed it on a tiny synthetic Game Gear ROM (the demo ROM from a private script (not published)) for four requests; a second agent wrote adversarial tests (`tests/test_sega8_extra.py`); a third compared the Z80 decoder with the clrhome.org table; a fourth reviewed the whole branch. Nothing ran in a window. No commercial Game Gear or Master System ROM was available.

## Scenarios

| Request | Outcome |
|---|---|
| A friend's code (`3A6-24E-2A2`) | `decode`/`vet`: patches `$1624` only if the byte is `$32`, the ROM holds `$FF`, so it does nothing here; labelled Traced, with a pre-mortem naming the wrong game or revision. Honest. |
| "Make the screen blue" | Found the two immediates from the listing, produced two codes that must be used together, labelled Traced (not Confirmed), noted it had not checked that nothing rewrites colour RAM later. |
| "Infinite lives" | No lives exist in the ROM; gave no code and said what would be needed. |
| "Make it work on my Master System" | Said Galoob hardware existed for Game Gear only, codes are emulator-format; but noted the docs did not say a Game Gear ROM will not run on a Master System. |

## Changes made

- `references/sega8.md` practical notes: Game Gear vs Master System ROMs and colour RAM, finding the live bank, 6-digit codes apply in every bank, RAM range, compare mismatches, `NOP ; DD`.
- `xrefs` now says when it found nothing; `disasm` no longer blames a missing `--bank` when one was given.
- Adversarial pass: nine defects fixed (bank-edge reads shared with Game Boy, prefix back-up in `vet`, `xrefs` at the last byte, error messages for unbanked ROMs, `patch-copy` usage). Review pass: `xrefs` on 48 KB ROMs (branch targets), `vet` behind a useless prefix.
- Z80 decoder vs clrhome: 699 documented cells, no real mismatches; undocumented-prefix handling differs by design.

## Deferred minors

- `is_vector_area` flags `$7FF0`-`$7FFF` in every bank and misses headers at `$3FF0`/`$1FF0`.
- `product_code` prints four digits; the real code may carry a fifth in the high nibble of `+E` (unverified).
- The header size nibble is shown but never compared with the file size.
- `--bank` on a no-mapper ROM at `$4000` or above is range-checked and otherwise ignored.
- Sega-mode error messages still say "a Game Boy code" for digit-count and value errors.
- `DD 76` decodes as a two-byte `HALT` while other no-HL cases show `NOP ; DD`.
- `vet` does not set `opcode-class-change` for a prefixed instruction when the opcode byte follows the prefix.

## Limits

One run per scenario on a synthetic ROM, by a fresh agent that could read the repository. The letters were corroborated headlessly with Genesis Plus GX's own cheat decoder (`docs/evals/sega8-letters.md`) but the author's run is pending, and banked addresses and Master System content have no emulator evidence.
