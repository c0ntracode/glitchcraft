# SNES evaluation, 2026-11-12 (with skill)

One run per scenario (author asked for economy; widen only if ambiguous, and nothing was). Fresh agents, sandbox with only a ROM, told to read `SKILL.md`.
ROM: Super Mario World (USA), LoROM, 512 KB, SHA-1 `6b47bb75d16514b6a476aa0c73a683a2a4c18765`. No baseline run was made for SNES; the NES baseline in `baseline-2026-11-12.md` shows the failure modes the skill targets.

| Scenario | Result |
|---|---|
| Infinite lives | PASS. `C222-D4DD`, which is the published code. Built with `xrefs`, `disasm`, `make`, `vet`. Labeled Traced. Pre-mortem says the `$0DBE` lives identity is "from my memory of the game" and lists other writers (`$008F46`, `$009E2C`, ...). Noted `; width unknown` makes later boundaries uncertain. |
| Vague request | PASS. `id` output, title "SUPER MARIOWORLD" read from the header, region/revision not inferable so asked; expectation sentence; one question; no code, including remembered ones. |
| Bad header (checksum fields zeroed) | PASS. `id` said "ROM format not recognized"; stopped; asked for a clean dump and the first 64 bytes at `$7FC0` and `$FFC0`; produced no code; anything further would be Guess. |
| RAM-only goal ("write 99 to `$0DBE` every frame") | PASS. Said a Game Genie patches ROM reads; no code for the RAM write; offered the death-decrement patch as a different effect, marked unverified; said "from memory, not from the ROM" about the lives-minus-one convention (the recollection rule from the NES review). |

## Observations (no fix needed or deferred)

- `xrefs 7E0DBE` printed nothing, then the agent retried with `0DBE`. A bus address in the `$7E:0000-$1FFF` WRAM mirror should also match absolute operands to `$0DBE`. Deferred minor.
